## 1. Что мы сделали и зачем

Главная фича фронтенда — **блочный редактор новостей**:

- добавление блоков: **текст** (с форматированием), **картинка**, **цитата**, **код** ⭐, **файл**;
- редактирование каждого блока, перемещение вверх/вниз, удаление;
- **предпросмотр** статьи (переключение «Редактор / Предпросмотр»);
- сохранение черновика, **публикация сейчас** и **отложенная публикация** (по дате).

Всё это реализовано функциональными компонентами и хуками — ровно как требует ТЗ.

## 2. Ключевая идея: «редактор = массив блоков»

Весь редактор — это один `useState<Block[]>`. Каждый блок — объект `{ type, ...поля }`:

```ts
const [blocks, setBlocks] = useState<Block[]>([]);
```

| Действие | Реализация |
|---|---|
| Добавить | `setBlocks(prev => [...prev, createEmptyBlock(type)])` |
| Изменить | `setBlocks(prev => prev.map((b, i) => i === index ? next : b))` |
| Удалить | `setBlocks(prev => prev.filter((_, i) => i !== index))` |
| Переместить | свап двух элементов по индексу |

**Почему это красиво:** этот же массив уходит на бэкенд как `blocks`, а MongoDB хранит его в поле новости. **Данные не трансформируются** — что редактируешь, то и сохраняешь, что сохраняешь, то и читаешь. Одна структура на три слоя: редактор → API → база.

## 3. Управляемые компоненты (controlled components)

В React значение `<input>`/`<textarea>` может жить «где-то там» в DOM, а может быть **управляемым** — то есть привязанным к состоянию:

```tsx
<input value={block.text ?? ''} onChange={(e) => onChange({ ...block, text: e.target.value })} />
```

`value` всегда берётся из состояния, `onChange` перезаписывает состояние. Единственный источник правды — блок в массиве. Это и есть управляемый компонент: интерфейс никогда не «расходится» с данными.

## 4. Компоненты фазы

```
frontend/src/components/editor/
├── blocks/
│   ├── TextBlock.tsx    # текст + style (paragraph/h1/h2/bold/italic)
│   ├── ImageBlock.tsx   # url + caption
│   ├── QuoteBlock.tsx   # text + author
│   ├── CodeBlock.tsx    # code + language
│   └── FileBlock.tsx    # url + name + size
├── BlockEditor.tsx      # «роутер»: какой редактор по типу блока
├── BlockPreview.tsx     # рендер блока для предпросмотра
├── Toolbar.tsx          # кнопки «+ Текст / Картинка / …»
├── UploadButton.tsx     # загрузка файла → /api/upload → url
└── Editor.tsx           # ядро: blocks, перемещение, предпросмотр, публикация
```

**BlockEditor** — пример композиции: он не знает про редактирование, а только «маршрутизирует» по `block.type`:

```tsx
switch (block.type) {
  case 'text':  return <TextBlock block={block} onChange={onChange} />;
  case 'image': return <ImageBlock block={block} onChange={onChange} />;
  // ...
}
```

**UploadButton** — использование `FormData` + axios: выбираем файл, шлём `POST /api/upload`, получаем `{ url, name, size }`, и `Editor` подставляет этот url в блок image/file. Так картинки и файлы сразу попадают в статью по реальному адресу.

## 5. Публикация через Editor

`save(publishNow)` собирает тело запроса:

```ts
const body = { title, blocks };
if (publishNow) body.publishNow = true;
else if (publishAt) body.publishAt = publishAt; // 'YYYY-MM-DDTHH:mm'
```

- «Опубликовать сейчас» → бэкенд ставит `status: 'published'` (см. `news.controller.js`);
- «Отложить» → `publishAt` в будущем, бэкенд ставит `status: 'draft'` и фильтр при чтении покажет статью после наступления даты (ADR 0001).

Редактор ничего не знает о таймерах — он просто передаёт дату. Это и есть «публикация = данные, а не таймер» на уровне UI.

## 7. Альтернативы, которые мы рассмотрели (и почему нет)

| Решение | Альтернатива | Почему выбрали так |
|---|---|---|
| **Свой блочный редактор (массив блоков)** | Готовые: TipTap / Slate / Lexical / Quill | ТЗ: «написать код самому»; свой редактор — учебная ценность; структура совпадает с моделью News |
| **Контролируемые инпуты (value + onChange)** | Неуправляемые (defaultValue + ref) | Управляемые гарантируют синхронизацию UI ↔ состояние |
| **`key={index}` для блоков** | UUID-ключи | Для учебного проекта индексы достаточны: блоки редактируются на месте |
| **Компоненты-роутер (BlockEditor)** | Один гигантский switch в Editor | Композиция: каждый тип — отдельный файл, легко расширять |
| **Загрузка файла по кнопке** | drag-and-drop | Проще; DnD — полировка (фаза 9) |
