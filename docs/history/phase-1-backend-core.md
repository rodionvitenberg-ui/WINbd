## 1. Что мы сделали и зачем

Мы подняли **каркас backend**: Express-приложение, которое умеет отвечать на HTTP-запросы, и подключение к MongoDB Atlas через Mongoose.

**Что получили:** сервер с точкой `/api/health`, которая возвращает JSON `{ status: "ok", ... }`. Это «лакмусовая бумажка»: если сервер отвечает на health-check — значит, каркас живой.

**Зачем так рано БД?** Потому что все следующие фазы (авторизация, новости) работают с данными. Сервер без базы — это пустышка. Подключение к БД — часть фундамента, и его лучше проверить в самом начале, а не обнаружить проблему на фазе 2.

## 2. Ключевые концепции

### 2.1. Express — веб-фреймворк Node.js

**Express** — самая популярная библиотека для HTTP-серверов на Node.js. Она даёт:

- **Маршрутизацию**: `app.get('/api/health', handler)` — «когда придёт GET-запрос на /api/health, вызови handler».
- **Middleware**: функции, которые обрабатывают запрос *до* попадания в маршрут.
- **Удобные ответы**: `res.json()`, `res.status()`.

**Альтернативы Express:**
- **Fastify** — быстрее, но менее «каноничный», для изучения не нужно.
- **Koa** — минималистичный, требует больше ручной работы.
- **Встроенный `http` модуль Node.js** — без фреймворка вообще: придётся вручную парсить URL, методы, тела запросов — это боль.

Мы выбрали Express, потому что это *стандарт индустрии* для JavaScript API: огромное комьюнити, масса готовых middleware, максимум учебных материалов. В ТЗ прямо указан Express — спорить не о чем. 😄

### 2.2. Middleware — «конвейер обработки запроса»

Представь запрос как **конвейер на заводе**: он проходит через несколько станций, прежде чем попасть к «ответственному за деталь» (маршрут):

```
Запрос в браузере
      │
      ▼
 cors() ────────► вешает заголовки CORS (разрешает/запрещает кросс-домен)
      │
      ▼
 express.json() ─► читает тело запроса (если JSON) → req.body
      │
      ▼
  маршрут ───────► выполняет логику → res.json(...)
      │
      ▼
 Ответ браузеру
```

Каждый `app.use(...)` добавляет «станцию» на конвейер. Это и есть middleware. У нас три:

1. `cors()` — решает проблему **CORS** (см. ниже).
2. `express.json()` — парсит JSON-тело запроса в `req.body`.
3. `express.urlencoded()` — парсит тела форм.

**Почему cors() должен быть ДО маршрутов?** Потому что middleware применяются по порядку. Если маршрут уже ответил — cors() просто не успеет отработать, и браузер заблокирует кросс-доменный ответ.

### 2.3. CORS — «пропуск» для кросс-доменных запросов

**CORS** (Cross-Origin Resource Sharing) — политика браузера: страница с домена A **не может** по умолчанию делать запросы к домену B.

```
Браузер: страница на http://localhost:5173 (наш фронтенд, Vite)
        │
        ▼  запрос к http://localhost:5000 (наш API)
        
Браузер спрашивает сервер: «А можно ли странице с :5173 читать твои ответы?»
Сервер отвечает заголовком:  Access-Control-Allow-Origin: http://localhost:5173
```

Без `cors()` наш фронтенд не смог бы обращаться к API — браузер заблокировал бы ответ. И это **защита**: CORS не даёт вредоносным сайтам читать чужие API.

Мы разрешаем только наш фронтенд (`CORS_ORIGIN=http://localhost:5173`). Не `*` (все) — это правильно для продакшна.

### 2.4. dotenv — секреты из файла `.env`

Файл `.env` содержит чувствительные данные: пароль БД, JWT-секрет. Его **нельзя** класть в git (это секрет!). Поэтому:

- в git живёт только **шаблон** `.env.example` (с заглушками);
- реальный `.env` создаётся локально копированием шаблона;
- `dotenv` при старте читает `.env` и кладёт значения в `process.env`.

```js
// server.js (самая первая строка!)
require('dotenv').config();
// теперь process.env.PORT, process.env.MONGO_URI доступны
```

**Почему dotenv ДО всего остального?** Потому что `app.js` и `db.js` читают `process.env` — они должны увидеть значения уже загруженными.

### 2.5. Mongoose — мост между Node.js и MongoDB

**MongoDB** хранит документы (похоже на JSON). **Mongoose** — библиотека-ODM (Object Document Mapper, аналог ORM в SQL-мире). Она даёт:

- удобные **схемы** (какие поля и какого типа у документа);
- **валидацию** (например, `email` обязателен);
- удобный API: `User.findOne({ email })` вместо ручных SQL-запросов.

`mongoose.connect(uri)` — подключается к базе. Строка подключения Atlas выглядит так:

```
mongodb+srv://<user>:<password>@<cluster>.mongodb.net/<dbname>?retryWrites=true&w=majority
```

Здесь `<user>`/`<password>` — пользователь БД, который создаётся в Atlas (это НЕ аккаунт Atlas!), `<cluster>` — адрес кластера, `<dbname>` — имя нашей базы (например, `winbd`).

### 2.6. nodemon — автоперезапуск при изменениях

В разработке мы меняем код постоянно. Ручной перезапуск (`Ctrl+C` → `node src/server.js`) утомляет. **nodemon** следит за файлами и сам перезапускает сервер при любом изменении. Это **dev-зависимость**: в продакшене она не нужна.

## 3. Структура файлов (и почему так)

```
backend/
├── package.json          # «паспорт» проекта: имя, скрипты, зависимости
├── .env.example          # шаблон переменных окружения (в git)
├── .env                  # реальные секреты (НЕ в git — создаётся локально)
├── uploads/              # загруженные файлы (пустая, с .gitkeep)
└── src/
    ├── server.js         # ТОЧКА ВХОДА: dotenv → createApp → БД → listen
    ├── app.js            # настройка Express: middleware + маршруты
    └── config/
        └── db.js         # подключение к MongoDB (mongoose.connect)
```

**Почему так разделено?**

| Файл | Отвечает на вопрос |
|---|---|
| `server.js` | «Как запустить сервер?» |
| `app.js` | «Как настроено приложение?» |
| `db.js` | «Как подключиться к базе?» |

Это **разделение ответственности**. App можно тестировать без реального запуска сервера; db можно переиспользовать; server остаётся коротким. В больших проектах это критично — в нашем просто полезно с самого начала.

## 4. Подробно о каждом файле

### 4.1. `package.json` — что здесь важно

```json
{
  "name": "winbd-backend",
  "main": "src/server.js",
  "scripts": {
    "dev": "nodemon src/server.js",
    "start": "node src/server.js"
  }
}
```

- `main` — точка входа, о которой «знает» Node.
- `scripts.dev` — для разработки: nodemon + автоперезапуск.
- `scripts.start` — для продакшена: обычный `node`.

### 4.2. `config/db.js` — подключение к БД

```js
async function connectDB() {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI);
    console.log(`MongoDB подключена: ${conn.connection.host}`);
  } catch (error) {
    console.error(`Ошибка подключения к MongoDB: ${error.message}`);
    process.exit(1);
  }
}
```

Ключевые моменты:

- `mongoose.connect()` возвращает **Promise** — «обещание». `await` ждёт его завершения.
- `try/catch` — перехватываем ошибку подключения.
- `process.exit(1)` — завершаем процесс с кодом ошибки. **Почему?** Сервер без БД бесполезен: лучше упасть сразу с понятной ошибкой, чем «работать» и падать на каждом запросе.

### 4.3. `app.js` — приложение

```js
function createApp() {
  const app = express();

  app.use(cors({ origin: corsOrigin }));      // до маршрутов!
  app.use(express.json());
  app.use(express.urlencoded({ extended: true }));

  app.get('/api/health', healthHandler);       // наш первый маршрут

  app.use((req, res) => res.status(404).json({ message: 'Маршрут не найден' }));

  return app;
}
```

Порядок регистрации middleware важен: конвейер строится сверху вниз.

### 4.4. `server.js` — запуск

```js
require('dotenv').config();          // 1. секреты из .env
const createApp = require('./app');
const connectDB = require('./config/db');

async function startServer() {
  const app = createApp();           // 2. приложение
  await connectDB();                 // 3. БД — если ошибка, процесс умрёт здесь
  const PORT = process.env.PORT || 5000;
  app.listen(PORT, () => console.log(`API сервер запущен: http://localhost:${PORT}`)); // 4.
}
```

**Почему `await connectDB()` именно здесь, а не в server.js до создания app?** Так мы гарантируем: без БД сервер не стартует. Осознанная политика «fail fast».

## 6. Альтернативы, которые мы рассмотрели (и почему нет)

| Решение | Альтернатива | Почему выбрали так |
|---|---|---|
| **Express** | Fastify / Koa / голый `http` | Стандарт индустрии, больше всего учебных материалов |
| **Отдельные `app.js` / `server.js`** | Всё в одном файле | Разделение ответственности, тестируемость |
| **`cors({ origin })`** | `cors()` без аргументов (`*`) | Безопаснее: разрешаем только наш фронтенд |
| **`process.exit(1)` при ошибке БД** | Логировать и продолжить | «Fail fast»: сервер без БД бесполезен |
| **`.env.example` в git** | Класть `.env` в git | Секреты не должны утекать |
