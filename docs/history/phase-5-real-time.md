## 1. Что мы сделали и зачем

ТЗ (звёздочка): «*Настроить уведомления (real-time взаимодействие) при создании-изменении-удалении новостной статьи*».

Мы подключили **Socket.io**:

| Событие | Когда | Данные |
|---|---|---|
| `news:created` | создана новость | `{ id, title, status }` |
| `news:updated` | изменена новость | `{ id, title, status }` |
| `news:deleted` | удалена новость | `{ id, title }` |

Клиент (фронтенд/колокольчик — Фаза 8) подключается к серверу **один раз** и получает события **мгновенно**, без опросов.

## 2. Ключевые концепции

### 2.1. HTTP vs WebSocket

**HTTP** — «спросил-получил»: клиент отправляет запрос, сервер отвечает, соединение (в простом случае) закрывается. Сервер **не может сам** «толкнуть» данные без запроса.

**WebSocket** — постоянный двусторонний канал. После рукопожатия (`ws://`) обе стороны могут слать сообщения в любой момент:

```
HTTP:   Клиент ──запрос──▶ Сервер ──ответ──▶ Клиент (связь кончена)
WebSocket: Клиент ◀────────── СЕРВЕР И САМ МОЖЕТ СЛАТЬ ──────▶ Клиент
```

**Socket.io** — библиотека поверх WebSocket: добавляет переподключение, комнаты, откат на другие транспорты (если WebSocket заблокирован). Это «WebSocket с удобствами».

### 2.2. Почему нужен «синглтон» (utils/socket.js)

Проблема: экземпляр Socket.io создаётся **один раз** при старте сервера, а события надо слать из контроллеров при HTTP-запросах.

Решение — общий модуль-хранилище:

```js
let io = null;

function initIO(server) { io = new Server(server, {...}); ...; return io; }  // server.js
function getIO()        { if (!io) throw new Error('не инициализирован'); return io; }  // любой контроллер
```

Контроллер вызывает `getIO().emit('news:created', ...)` — как будто «берёт с полки» уже готовый сервер.

### 2.3. Почему в server.js появился `http.createServer(app)`?

Раньше было `app.listen(PORT)` — Express сам создавал HTTP-сервер. Но Socket.io нужно передать **именно тот** HTTP-сервер, на котором работает приложение:

```js
const server = http.createServer(app); // сейчас
initIO(server);                        // Socket.io поверх того же сервера
server.listen(PORT);
```

### 2.4. `emit` — «разослать всем»

`io.emit(event, data)` шлёт событие **всем подключённым клиентам**. Именно это нужно для уведомлений: любой клиент (список новостей, колокольчик) мгновенно узнаёт об изменениях.

## 5. Альтернативы, которые мы рассмотрели (и почему нет)

| Решение | Альтернатива | Почему выбрали так |
|---|---|---|
| **Socket.io** | Чистый `ws` (WebSocket), SSE (Server-Sent Events), поллинг | Socket.io устойчив (`+reconnect`, фоллбэк транспортов); SSE — только сервер→клиент; поллинг — «велосипед» |
| **Синглтон getIO()** | Прокидывать io через аргументы в каждый контроллер | Меньше связности: контроллер сам «берёт» io |
| **`news:created` / `news:updated` / `news:deleted`** | Одно событие `news:change` | Клиент по имени события понимает, что именно произошло |
| **`http.createServer`** | `app.listen()` | Нужно передать сервер в Socket.io |
| **Публичный emit всем** | Комнаты/персональная рассылка | Уведомления о новостях всеобщие по смыслу |
