# Отложенная публикация реализована как данные, а не как фоновый таймер

Решение: у новости есть поля `status: 'draft' | 'published'` и `publishAt: Date`. «Отложенная публикация» — это сохранение будущей даты с сохранением статуса черновика; «публикация» происходит в момент запроса через фильтр `status === 'published' && publishAt <= now`. Никаких фоновых задач и таймеров на сервере.

Почему так: таймер (setTimeout / Node-планировщик / cron) умирает при перезапуске сервера, усложняет горизонтальное масштабирование и требует отдельной инфраструктуры. Data-driven подход переживает рестарты, прост в реализации и отлично ложится на document-модель MongoDB, где статья — один документ.

Альтернатива (отклонена): запуск отложенной задачи при сохранении новости и/или периодический cron-проход. Сложнее, хрупче, без видимой выгоды для масштаба нашего проекта.

Следствие: поле `publishAt` остаётся в документе даже после публикации (история, когда статья «вышла»).
