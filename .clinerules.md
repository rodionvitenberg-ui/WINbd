# WINbd — правила проекта (для ИИ-агентов и разработчиков)

> Этот файл живёт в корне репозитория `WINbd` и является **единым источником правил** для всех будущих агентов, работающих над проектом. Глобальные правила пользователя не изменяются.

## 1. О проекте

- **Monorepo:** `./backend` — REST API на Node.js + Express + MongoDB (Mongoose), `./frontend` — SPA на Next.js (App Router) + TypeScript.
- **Задача:** редактор новостных статей (тестовое задание) — JWT-авторизация, CRUD новостей с отложенной публикацией, загрузка файлов, real-time уведомления, блочный редактор, предпросмотр.
- **Режим обучения:** владелец проекта изучает Node.js и MongoDB. **Каждый шаг** должен начинаться с объяснения «почему так, а не иначе», какие были альтернативы и почему выбран именно этот путь.
- Полный контекст — в `CLAUDE.md`; план — в `ROADMAP.md`; учебник по фазам — в `docs/history/`.

## 2. Окружение и команды (проверять ДО каждой команды)

- **Backend:** все команды из `./backend`:
  - разработка: `cd backend && npm run dev` (nodemon, автоперезапуск);
  - продакшн-старт: `cd backend && npm start`;
- **Frontend:** все команды из `./frontend`:
  - разработка: `cd frontend && npm run dev` (Next.js dev-сервер);
  - сборка: `cd frontend && npm run build` (Next.js build);
  - запуск собранного: `cd frontend && npm start`.
- Терминал неинтерактивный: всегда использовать неинтерактивные флаги (`--noinput`, `-y`).
- Запущенные серверы обучения/разработки не перезапускать без необходимости.

## 3. Конвенции кода (требования ТЗ)

- **Backend:** обязательный JSDoc на **русском языке** у каждой функции, роута и middleware. Комментарии — только русские.
- **Frontend:** **только функциональные компоненты** (никаких классовых) и хуки. TypeScript, как и на бэкенде, обязателен (типы для API — в `frontend/src/types`).
- Никаких `TODO`, заглушек, «остальной код не привожу» — пишется полный рабочий код.
- Код пишется самостоятельно, а не копируется со StackOverflow.
- Переменные, функции, файлы — осмысленные названия. Домен описан ниже.

- **Каждая фаза** — отдельный файл-учебник `docs/history/phase-XX-nazvanie.md`, написанный человеческим языком: цель, объяснение концепций, альтернативы, выбранный путь, **команды, которые использовались**, примеры кода, вопросы для самопроверки.

## 6. Доменная модель (уточняется в фазах 2–3)

- **User:** `email`, `passwordHash` (bcrypt). JWT в payload несёт `userId`.
- **News:** `title`, `blocks[]` (массив блоков), `author` (ObjectId пользователя), `status: 'draft' | 'published'`, `publishAt: Date` (для отложенной публикации).
- **Блоки статьи** (каждый — объект с полем `type`):
  - `text` — абзац/заголовок/жирный/курсив;
  - `image` — url + подпись;
  - `quote` — текст + автор;
  - `code` — кусок кода + язык;
  - `file` — загруженный файл (pdf, doc и т.п.).
- **Отложенная публикация — это данные, а не таймер:** статья со `status: 'draft'` и `publishAt` в будущем публикуется «в момент запроса» через фильтр `status === 'published' && publishAt <= now`.
